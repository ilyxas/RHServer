# 005. One agent on the channel, any agent: the name from `[channel] agent`

- Пункт SPEC: friend slice 1–2 (friend.send, friend.decide, гейт); задание владельца в PR #16 и #17
- Дата: 2026-10-23
- Статус: утверждено владельцем (ревью PR #17, 2026-10-23 19:41Z) с добавками 1–6 ниже
- Источник: docs/any_single_agent.md; ревью владельца в PR #17

## Вопрос

Имя агента «Friend» было зашито в контракт (`to: const Friend`), ядро, хуки, конфиги, приложение
и документацию. Владелец хочет на канале одного агента, но любого, и менять его в любой момент.
Несколько агентов одновременно — не в объёме.

## Вывод

- Имя задаётся в одном месте: `[channel] agent` в конфиге ядра (вместе с `project_dir` и
  `target`, все обязательны, без default). Всё остальное читает его: `status.channel`
  для приложения, `to` в friend.send / friend.decide, записи журнала (`agent`), заголовки Log
  и Home, конфиг стороны агента (`rhcore friend-config`, `rhcore channel set`).
- Контракт 0.5.0: `to` — шаблон id вместо `const Friend`; `status.channel {agent, title}`;
  векторы с `Agent-Alpha`. Подпись, op и ключи не меняются.
- «friend» остаётся именем механизма (пути `/v1/friend*`, op `friend.*`, схемы, программы
  `rh-friend-*`, таблицы, события) — в честь агента, который его спроектировал и первым на
  нём работал; к текущему агенту канала отношения не имеет.

Добавки владельца (ревью PR #17):

1. `rhcore channel set` сам перезапускает ядро и проверяет, что `status.channel` = новое имя;
   иначе — ошибка, не «готово». Сделано: перезапуск через `launchctl kickstart -k`, проверка
   через admin-сокет, код 1 и сообщение при несовпадении.
2. Team file не роняет ядро при старте: id нет в team file — показывается сам id, в журнале
   `friend.channel.warning`. Проверка «id есть в team file» — только в `channel set` (там же
   проверка коллизии регистра).
3. tmux target хранится явно (`[channel] target`), не выводится из id; `channel set`
   проверяет `tmux has-session -t <target>`.
4. Live-тест: после смены прежний агент не получает ✔ и не может выполнить защищённое
   действие. Механизм: его хуки указывают на прежний `--project`, конфиг — на новый, verifier
   и gate закрываются (fail closed); его неиспользованные allow аннулированы ядром.
   Автотесты в `tests/test_channel.py`; живой шаг 10 в docs/friend-gate.md.
5. Имя спрашивающего агента на карточке вопроса в приложении — RHClient, отдельный PR (d).
6. Строка в docs/friend-gate.md про имя механизма — есть.

Порядок PR (решение 4): контракт, ядро и сторона агента (a, b, c) — один серверный PR;
iOS (d) — отдельный.

## Следствие для кода

- Конфиг ядра без `[channel]` не стартует; старая секция `[friend]` — ошибка с указанием на
  docs/friend-gate.md. `team_file` без default.
- Schema 4: колонка `agent` в `friend_questions`/`friend_decisions`, таблица `channel`; при
  старте ядро привязывается к агенту из конфига, при смене — withdraw/void прежнего и событие
  `friend.channel.changed`.
- Установка до этого изменения обновляется по docs/friend-gate.md «Install», шаг 1–3.
